# EvidenceTrail — Muse Spark Hackathon Submission Guide

EvidenceTrail is built around Muse Spark requirement mapping and source-verified CV evidence. This guide maps the public event criteria and the event-detail screenshots shared by the entrant to the product design. The organizer’s official rules and waiver remain the controlling documents; the selected entrant must read and accept them in the submission flow.

**Current runtime state (30 October 2026):** the default public judge path uses saved results and does not make fresh Muse calls; local simulation is separate and is not Muse analysis. The repository contains a 20-CV saved Muse replay and a separately recorded 12-pair / 24-request research replay. Cumulative draft PR #28 is at `5c20bd2bdf620c00aa6f66938fc3ee09ca5f6674`; its mock acceptance, browser smoke, and CI passed, but it is not deployed. Public parity still reports deployed SHA `bd9a0a1e5a95da4dbeec3e995a9bd3089a984c6a`. The standalone redesign prototype is in separate draft PR #38 and is not included in PR #28. No public paid Muse call is enabled.

## Before submission

1. The default build is local-only. If you choose to reactivate Muse, set `EVIDENCETRAIL_PROVIDER=muse`, `EVIDENCETRAIL_ENABLE_MUSE=true`, and `MODEL_API_KEY` only in the hosting provider’s server-side settings. Never put the key in browser code, the repository, or the recording.
2. If Muse is re-enabled, run the single-pass text-first analysis flow and inspect the actual semantic result, citation checks, graph links, page highlights, latency/token telemetry, and exported evidence pack. Otherwise, use only the clearly labeled saved replay and state that it is historical.
3. Record the demo from the same build. Show the real saved response or new live response and explain what the local source checks do.
4. Review both public-JD calibration profiles before recording. The named-system prompt trial kept aggregate label accuracy unchanged and shifted the remaining miss; do not describe it as an accuracy fix. Show the timeline gate as deterministic adjudication, not Muse accuracy, and keep the blocked quote from its separate run distinct from the clean 21/21 prompt-trial quote checks.
5. Check the app, repository, and video links from a signed-out browser.
6. Confirm the track, entrant/team and representative details, eligibility, and accepted rules in the submission flow.
7. Submit before 4 November 2026 at 9:00 PM ET.

## Product claims to preserve

- EvidenceTrail checks whether a quoted passage occurs in the supplied document; it does not verify a real-world credential or employment claim.
- “Not found” means the supplied CV did not provide verified support; it does not mean the candidate lacks the qualification.
- The batch view lists CVs in upload order and stores recruiter-entered shortlist choices; Muse and EvidenceTrail do not score or rank candidates or decide who is hired.
